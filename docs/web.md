# Web 契约索引

Web 的当前详细架构和 API 消费说明位于 [`docs/decisions/web.md`](decisions/web.md)。站点设置（`GET /api/v1/site`）驱动公开站点身份与首页组合：`title`/`description` 驱动浏览器标题与 SEO/RSS 元数据，`navigation` 驱动顶部导航（空回退内置三项），`footer`/`social` 驱动页脚底行与链接，`commentsEnabled=false` 时详情页不渲染评论区（Core 公开评论接口同时 403 兜底），`sections`（`PROFILE/BACKGROUND/RECENT_CONTENT/UPDATES/SERIES/CONTACT` 枚举）驱动首页区块内容与顺序（锚点随之派生），首页内容列按发布时间排序展示；hero headline 下渲染一行 mono 统计（`articleCount/thoughtCount/wordCount` 的 `N writings · N thoughts · N words`）。首页其余结构包含 Background 的 Education/Experience 双列区块、左右双栏 Writings/Thoughts 时间线（各最多 3 条，每行在相对日期与阅读时长下渲染 `views · likes · comments` 统计，不再叠加绝对日期；双列下方渲染 `client.tags()` 前 8 个标签的 Top tags 展示行，tags 请求独立降级）、按 `publishedAt` 升序铺满 Core 返回的最新范围的横向 Updates 轨道（月份刻度下带春/夏/秋/冬季节色带；顶部地图缩放式按钮（区块头部右侧，与 hint 同排）展开面板：连续滑块（0–100）平滑缩放窗口（默认最近 7 天，锚定最新内容），Reset 恢复默认最近 7 天窗口，窗口内容重新拉伸撑满整条轨道，标签按轨道宽度自动减密；头部 hint 显示 `{contentCount} notes · {wordCount} words`）、My Series 索引卡片与纯图标 Contact 卡（实底 paper + hairline + 8px 圆角，与 Series 同语言；`profile.websiteUrl` 渲染为首个 Website 图标条目）；桌面区块间距统一 72px、≤768px 收窄为 44px。Series/Contact 详情使用挂载到 `document.body` 的最高层级 tooltip，内容仍由 Core 驱动。Thoughts 与 Writings 归档都通过 `content()` 按 kind 请求 Core 分页、`tag`/`q` 过滤、正文摘录和互动计数；Writings 额外支持排序与 No AI 过滤。两个归档共用 `useArchiveFilters` 客户端数据流：首屏由 Server Component 读取，后续筛选/翻页由 SDK 请求对应页并以 `history.replaceState` 同步 URL；置顶卡来自站点组合的 `pinnedThoughts` / `pinnedWritings`，只在默认视图展示，普通列表仍使用 Core `/content` 分页结果；tag 云与计数来自 `/api/v1/tags`，两页均提供 `View all tags` 弹出选择器（视口全局居中的固定面板）：展示全部 tag、允许多选（即时生效、点空白处或 Escape 关闭），选中的 tag 在 tag 云中浮动到最前（writings 顶部、thoughts 最左）。默认着陆视图首屏仅展示页头、置顶卡与底部居中的呼吸式下滑箭头提示，底部列表在用户手动滚动到位后才浮现（箭头可点击平滑下滑一屏，列表浮现的同时淡出）；筛选或排序状态下列表按 IntersectionObserver 逻辑自动浮现。Thoughts 与 Writings 卡片均把星号灰色摘要和正文摘录分开，普通项显示两行正文、置顶项显示四行。文章详情在标题阅读面上方单独显示返回 Writing 的入口，正文区域使用四段同宽的不透明阅读面、同排元数据、右侧标题进度目录；底部讨论面提供统计、搜索和筛选，添加评论面承载互动与表单，桌面/平板由左侧紧凑动作卡下滑淡出、底部添加评论面淡入（独立 layoutId，无跨位置布局动画），默认收起仅显示动作行（GitHub/Guest 登录图标、点赞、评论、分享），越过激活线后继续下滑保持底部状态，仅向上越回激活线才恢复左侧，布局变化时自动重算，手机端在讨论面之后堆叠。Thought 详情复用同一纸面语言但不使用阅读壳：标题面以 ✦ 灰色摘要、mood 徽标与点赞/观看/评论计数呈现 Thought 语境，question 以 serif 反思引言块突出，context/source 作 mono 脚注，标题面与正文面之间提供复用 Writing 目录轨道视觉的阅读进度轨（宽屏为正文右侧吸附竖轨，≤1300px 退化为正文面上方的横向进度行），讨论面与添加评论面作为两个独立块直接置于正文面下方。两个详情页共用统一的评论渲染：点阵头像（按种子确定性生成，GitHub 登录评论则用账号头像 URL 并附 `via GitHub` 徽标）、微信式左下尖角气泡、相对时间、hover 淡入的回复按钮与两级缩进的嵌套回复；评论身份（组合词默认名 + 可点选头像，或 GitHub 登录）保存在浏览器本地，GitHub 会话也可在动作行的 GitHub/Guest 图标间随时切换发布身份（访客模式提交不携带 GitHub Bearer，Core 记录为 visitor）；讨论面按顶层评论分页（每页 10 条，回复随顶层同页，`q` 服务端线程级搜索），分页器与两个归档共用 `components/pagination.tsx` 且单页隐藏；评论提交经过"遮罩转圈 → 对勾成功面板（View your comment 跳转新评论 / Comment again 再次编辑）"的状态流，成功面板持续停留直至用户操作，发布顶层评论后自动清空搜索并跳到最后一页。共同信息的展示参考根目录 `1.html`。全局导航提供 route-aware pills、⌘K/Ctrl+K 搜索、主题切换、RSS 与站点设置的外链。两个详情页均为 Dynamic Server Component，渲染时经 `next/headers` 读取 `referer` 并以 origin 形式传给 `contentBySlug` 的 `referrer` 参数，供 Core 浏览事件做来源分析；访客 ID 镜像到 `manifold-vid` cookie 后由详情页 SSR 附带 `X-Visitor-ID`，浏览事件按访客去重；`generateMetadata` 仍以 `trackView:false` 读取避免重复计数。

首页 Recent Content 每类读取 10 条公共内容后展示最近 3 条；Updates 通过 SDK `homeTimeline()` 一次读取 Core 的轻量、有限时间线投影（取最新内容后按首发时间升序），不在 Web 内循环抓取内容分页；截断时页面显示返回范围。RSS 使用独立的小页内容读取，不请求首页时间线聚合。

评论隐藏由 Core 返回的 `Comment.hidden` 表示：未软删的隐藏行保留线程位置，但公开响应不包含作者名、网站、正文或头像种子，Web 渲染固定占位符 `This comment was hidden by moderation.`；隐藏不级联回复，隐藏行也不参与公开搜索或 `comment_count`。评论相关事实以 `docs/decisions/web.md` 和 `docs/core.md` 为准。

`/chain` 是锚定链浏览器与验证页（契约见 [`docs/chain.md`](chain.md)）：1080px shell + 归档同款 eyebrow + serif H1 页头，右侧附 `● Mining` 脉冲徽标与 tip 哈希片段作为链实时状态指示；面板共享 paper surface + `Reveal` 渐显与 `prefers-reduced-motion` 守卫，分页器复用 `Pagination`。依次为：(1) 四列 `Height`/`Commitments`/`Proof`/`Site key` 概览（hairline 分割、serif 数值、mono 副标签）+ `genesis <hash> ─── tip <hash>` 链接带；(2) `Sealed sequence`——加载**整条已封链**（`chainBlocks({page:1,pageSize:100})` 一次拉全，Core 上限 100，个人站点规模够用；提交新块后自动重拉）并倒序为 genesis→tip 的横向节点链（`chainSpineCube` 区块号/哈希前缀/锚定数，节点间箭头连接，tip 用 accent 边框，hover 抬升 3px），`chainSpineNav` 两侧 chevron 按钮平滑滚动整条链（容器 `overflow-x:auto` + `scroll-behavior:smooth`，触摸可滑动，不再依赖底部账本分页）；选中节点显示 `chainSpineDetail` 字段卡（Block / Hash / Prev hash / Merkle root / Nonce / Target / Certificates / Sealed），卡内 `chainSpineJump` 按钮可跳转到下方账本对应块行并展开其证书（不在当前页时自动回到第 1 页）；URL 带 `?block=<id>` 时（详情页徽标深链）自动选中该块并滚动到 spine，旧块则展开账本行；(3) `Prove a commitment`——**左右分栏**（`chainVerifyGrid`，≤900px 窄屏堆叠）：左栏 `chainVerifyLeft` 为 `chainSegmented` 切换 Payload/SHA-256/Slug 三种模式 + 单输入控件 + Run verification 触发 `verifyPayload / verifyByHash / verifyContent`（Web 不做任何哈希/规范化），结果以 `chainReceipt[data-verdict]` 凭据卡呈现 verified（accent 边框 + ShieldCheck 图标）/ mismatch / not-found / error 四态，含 `chainCheckRow` 三项与（存在锚定时）`chainReceiptRows` 详情（Subject hash 可复制 + Source/label + Block `#n` 或 pending + Committed + Certificate）；verified 时凭据卡底部追加 `chainContext`「Chain position」：`prev → current → next` 三块**spine 同款 cube 节点**（`chainContextBlock` 复用 `chainSpineCube`/`chainSpineMeta`：区块号 cube + 哈希前缀 + 锚定数，`this cert` 当前块 accent 高亮，hover 抬升），每块带 `chainContextJump` 按钮跳转到底部账本对应行并展开（沿用 `openInLedger` 逻辑）；右栏 `chainVerifyRight` 为**验证过程 graph**（`chainGraphPanel`）：Core 返回的 `steps`（证书 lookup → ed25519 验签 → merkle 根 → 块哈希 → 全链重放）依次点亮（240ms/步，`chainGraphStep` 状态色 passed/failed/pending，无 hover tooltip，详情以点击展开为唯一入口），**点击**节点展开 `chainGraphDetail`——**以 `step.detail` 摘要（如 `sha256(preimage) == stored`、`leaf + 2 sibling(s) → root`）为引导行，展开完整计算明细**：块哈希步将 preimage 渲染为 7 段 `|` 分隔 pill（`data-preimage`，**完整值**）加 `sha256` 箭头，并追加 `data-compare` 完整对比行（recomputed / stored / match `=== ✓`，stored 取 context.current.hash）；其余步为名值数据网格（签名 publicKey/message/signature、链重放 height/indexChecks/prevLinks/merkleRoots/signatures 统计），merkle 步追加 `data-merkle-path` 完整审计路径（`leaf[i]` / `sibling[left|right]` / `root`，**完整值**）；中间计算逐层列出（`L1/L2…` 层级标号，完整值），结果以 `data-step-verdict` pill 收尾（`✓/✗` + 短数据文案）；(4) `Commit a payload`——textarea + 可选 label（≤64 字符）调用 `submitAnchor`；提交记录以**横向卡片网格**（`chainCommits`/`chainCommitCard`，auto-fill ≥300px）持久化在 `localStorage`（`manifold.chain.pendingCommits`，最多 8 条）：每卡展示提交原文（截断 3 行）、可选 label、Certificate/Subject hash（可复制）与状态，冷却期（10s）过后可继续追加多条；页面加载时对 pending 记录逐条 `verifyByHash`，已封块的自动升级为 `Sealed` + 块号（anchored 实线边框），刷新不丢失；提交后刷新当前页区块列表；(5) `Blocks` 账本——`chainSection` 沿用 `thoughtSectionHeading` 标题样式，行用 `chainLedgerRow`（`#index` + 哈希 `HashLine` 自动高亮 PoW 前导零 + `prev/root/nonce/proof` 元信息 + 锚定数 chip + UTC 时间 + chevron），每行带 `ledger-block-<id>` 锚点供 spine 跳转，左栏有 `chainLedgerSpine` 纵向虚线串联区块节点，hover 向 X+3px 位移并染 `accent-soft`；账本底部**始终**渲染共享 `Pagination`（Page x of y，即使单页也显示禁用态），页码写入 URL `?page=N`——浏览器 back/forward（如从证书跳转到内容页后返回）恢复原页码与列表；展开后 `chainLedgerDetail` 显示 `chainCertList`，`chainSourceChip` 含按 source 染色的圆点（content/visitor 走 accent，其他走 ink/muted），每行主体为 Core 派生的 `summary` 概述（如 `Writing “designing-boundaries” · published · v2`）加截断 subject hash（mono 小字），附状态（anchored 绿、pending accent）、`✓ signed` 标识（依据 `siteSignature` 非空）；存在可跳转目标（内容页/评论区锚点/媒体 URL，`AnchorTarget`）时行尾渲染圆形箭头按钮，无目标时占位保持对齐，并以 `chainDetailFoot` 标注 merkle 封证数量。底部 `How anchoring works` 面板以 `chainPrimer` 展示 01 Commit / 02 Sign / 03 Seal 三步（accent hairline + serif 标题 + 说明），随后 `chainFootnote` 提示"Verification replays the full chain on every check"。全部哈希/规范化由 Core 完成，Web 不复制链逻辑。Writing 与 Thought 详情页的标题 meta 行行尾右下角渲染锚定徽标（`ContentDetail.latestAnchor`：指纹前缀 + `block #N` 或 sealing 状态，无证书不渲染），已封块时点击跳 `/chain?block=<blockId>`——chain 页据此选中 Sealed sequence 对应块（超出 spine 窗口的旧块自动展开账本行），sealing 中则进 `/chain`。默认导航（站点设置 `navigation` 为空时）为 Home/Writings/Thoughts/Chain 四项。

本文只保留入口，避免 `docs/web.md` 与决策目录中的 Web 契约出现两份不一致的事实。修改 Web 路由、Core 请求、Markdown 渲染、评论/反应、SEO 或设计约束时，必须同步 `docs/decisions/web.md`，并检查本索引是否仍准确。
